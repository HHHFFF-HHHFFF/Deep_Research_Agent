# 架构说明与设计决策

## 一、一句话定位

这是一个本地单用户的个人深度研究助手：用户输入研究问题并可选上传资料，系统结合网页研究与 FAISS 本地 RAG，生成可查看、下载和恢复的中文 Markdown 报告。

## 二、核心架构

```text
React + TypeScript + Ant Design
  ├─ 主题、模型和文件输入
  ├─ 状态轮询、取消与刷新恢复
  └─ Markdown 报告查看和下载
                ↓ HTTP
FastAPI + Pydantic + SQLAlchemy
  ├─ 输入与上传安全校验
  ├─ SQLite 任务元数据
  └─ 单进程 AsyncIO 任务管理
                ↓
统一研究运行入口
  ├─ Qwen／DeepSeek 路由与备用模型
  ├─ 网页搜索、抓取、分析工具
  └─ 文档解析 → 切分 → Embedding → FAISS Top-K
                ↓
        中文 Markdown 报告
```

开发时 Vite 和 FastAPI 分别运行以保留热更新；生产演示时 FastAPI 托管 Vite 构建，只暴露一个本地端口。

## 三、关键技术选择

### 为什么前端使用 React，而不是 Streamlit

React 更适合明确表达文件上传、任务状态、取消、历史恢复和报告预览这些持续交互。Streamlit 开发更快，但重运行模型会让长任务状态控制和界面细节更难稳定。

### 为什么是 FastAPI + 轮询

研究任务耗时较长，创建任务后立即返回任务编号，前端再轮询固定阶段。首版本地单用户场景不需要 WebSocket 或 SSE，普通 HTTP 更容易测试、恢复和解释。

### 为什么 SQLite 和 FAISS 同时存在

两者保存的数据不同：SQLite 管理任务状态、文件关联和报告路径；FAISS 管理文档向量与相似度检索。SQLite 解决业务状态恢复，FAISS 解决语义检索，不能互相替代。

### 为什么只允许一个活动任务

现有 Agent、模型连接、工作目录和 FAISS 都运行在同一个进程中。单任务约束避免共享资源竞争，也符合个人演示项目的真实需求；为不存在的并发需求引入 Redis、Celery 会扩大部署与维护复杂度。

### 为什么聊天模型与 Embedding 分开配置

DeepSeek 可以负责推理和报告生成，同时使用 Qwen Embedding 构建 FAISS 索引。职责拆分避免因为切换聊天模型而失去本地 RAG，并允许各自降级。

## 四、核心技术难点

1. 将原本直接运行的研究流程提取为统一异步入口，让命令行和 FastAPI 复用同一套初始化、模型覆盖、阶段回调、取消和结果读取逻辑。
2. 为长任务建立最小状态机，把等待、运行、成功、失败、取消和中断写入 SQLite，并在刷新和重启后给出一致结果。
3. 对上传资料执行扩展名、文件结构、大小、总量、解析超时和文字长度限制，再复用内容哈希、Embedding 与 FAISS 检索。
4. 把网页和文档视为不可信证据，对证据标签转义，并明确禁止把资料中的命令当作系统指令执行。
5. 处理 React StrictMode 二次挂载、轮询清理、连续断线暂停和卸载后请求取消，避免记录持续加载和状态竞争。
6. 让开发模式保留前后端热更新，同时在演示模式中由 FastAPI 托管前端构建，实现一个命令、一个端口启动。

## 五、常见设计问题

### 这个 Agent 是“给一个方向就返回研究计划”吗？

不只是研究计划。它会把主题拆成待办，搜索和抓取网页，分析公开信息，并可结合本地文档 RAG，最终生成完整的中文 Markdown 初始研究报告。报告用于建立方向和证据基础，不替代正式学术审稿或专业结论。

### FAISS 和 ChromaDB 的 `as_retriever` 有什么关系？

用途相似，都是根据查询取回相关片段；但 FAISS 更接近底层向量相似度索引。这个项目自己负责切分、去重、metadata、Embedding、索引持久化和 Top-K 封装，没有依赖 ChromaDB 的 Retriever 接口。

### 如何取消研究任务？

任务管理器保存一个 `asyncio.Event`。用户取消后设置事件，统一研究入口在初始化和 Agent 执行边界检查它并协作式退出，随后把稳定终态写入 SQLite。它不是强制杀线程，因此工具内部不可中断的单次调用仍需等待返回。

### 页面刷新为什么能恢复？

任务每次状态变化都写入 SQLite。前端刷新后先查询活动任务，再读取最近 8 条记录，并按本地保存的任务编号恢复报告。正在运行的内存任务不能跨进程恢复，应用重启时会被标记为已中断。

### 如何防止提示注入？

系统把网页和本地文档统一视为不可信证据，在注入 Agent 上下文时增加明确边界、转义来源标签，并要求忽略资料内改变角色、索取密钥或调用工具的指令。文件上传和报告展示还分别限制格式、路径和原始 HTML。

### 为什么没有 Redis、Celery 和 Docker？

项目定位是本地单用户个人助手，一个进程和一个活动任务已经满足需求。增加分布式组件不会改善核心研究闭环，反而提高部署、调试和维护成本。若未来出现多用户、多进程或跨机器续跑需求，再重新设计任务队列和存储。

## 六、项目实现摘要

项目名称：深度研究智能体

项目描述：独立设计并实现本地单用户深度研究助手，支持 Qwen／DeepSeek 模型切换、网页搜索与抓取、PDF／DOCX 等本地资料解析、FAISS RAG、异步任务取消、刷新恢复和 Markdown 报告生成。

技术亮点：

- 使用 FastAPI、Pydantic、SQLAlchemy 与 SQLite 建立长任务 API 和稳定状态机，通过 AsyncIO 实现单活动任务、协作式取消与重启中断收敛。
- 使用独立 Embedding、内容哈希去重和 FAISS Top-K 4 检索，把本地资料作为不可信证据安全加入工具型 Agent。
- 使用 React、TypeScript、Vite 与 Ant Design 完成响应式研究界面、上传限制、轮询恢复和安全 Markdown 报告展示。
- 建立后端离线测试、Ruff、局部 mypy、编译检查以及前端类型检查、组件测试和生产构建门禁。

## 七、项目边界

首版明确不做账号、多租户、多人协作、分布式任务队列、实时推送、微服务和公开 SaaS。这个边界来自当前使用场景，后续只有在实际需求变化时才重新评估。
