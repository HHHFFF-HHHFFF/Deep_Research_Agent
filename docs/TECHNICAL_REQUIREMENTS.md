# 技术需求

## 一、技术栈

| 层次 | 技术 | 本项目用途 |
| --- | --- | --- |
| 研究核心 | Python 3.10、AsyncIO | 运行 Agent、模型、网页工具和单进程研究任务 |
| 后端接口 | FastAPI、Uvicorn | 提供文件、任务、状态、取消和报告接口 |
| 数据模型 | Pydantic v2 | 校验研究输入、配置和 API 数据 |
| 元数据存储 | SQLite、SQLAlchemy 2 | 保存任务状态、上传文件和报告路径，支持刷新恢复 |
| 前端 | React、TypeScript、Vite | 构建稳定的单页用户界面 |
| 组件库 | Ant Design | 提供成熟的表单、上传、提示和状态组件 |
| 报告展示 | react-markdown | 安全展示 Markdown，不启用原始 HTML |
| 配置 | MMEngine Config、python-dotenv | 加载场景配置、模型选择和本地密钥 |
| 大模型 | Qwen、DeepSeek、OpenAI 兼容接口 | 执行工具调用、分析和报告生成 |
| 网页研究 | Crawl4AI、DDGS、HTTPX | 搜索、抓取和解析网页资料 |
| 本地 RAG | FAISS、Qwen Embedding | 对本地文档建立向量索引并检索 |
| 质量检查 | pytest、Ruff、mypy、前端类型检查与组件测试 | 保证接口、研究流程和关键交互可靠 |

## 二、运行架构

- Python 使用 3.10 或更高兼容版本，当前开发环境为 Python 3.10.20。
- 开发时 FastAPI 和 Vite 分别启动，Vite 通过代理访问 `/api`。
- 生产演示时由 FastAPI 托管 Vite 构建后的静态文件，只需启动一个服务。
- 后端采用单进程运行，不能配置多个 Uvicorn worker。
- 同一时间最多执行一个研究任务，避免共享模型、文件和 FAISS 资源发生竞争。
- 长任务由进程内 AsyncIO 任务管理器运行，前端每 1 至 2 秒轮询状态。
- 首版不使用 FastAPI `BackgroundTasks` 承担研究生命周期，而由应用级任务管理器保存任务句柄、取消信号和状态更新。
- 应用关闭后无法继续运行中的研究；重新启动时把遗留任务标记为“已中断”。

## 三、API 需求

- 所有业务接口使用 `/api` 前缀。
- `GET /api/health` 返回服务可用状态。
- `POST /api/files` 上传并校验研究资料，返回不可猜测的文件编号。
- `POST /api/tasks` 接收主题、模型选择和文件编号，返回任务编号。
- `GET /api/tasks` 只返回有限数量的最近任务。
- `GET /api/tasks/{task_id}` 返回状态、阶段、时间和安全化错误信息。
- `POST /api/tasks/{task_id}/cancel` 发出协作式取消信号。
- `GET /api/tasks/{task_id}/report` 只允许读取已完成任务的报告。
- API 使用一致的错误结构，不能把堆栈、密钥、绝对路径或模型请求头返回前端。
- Pydantic 负责字段长度、枚举和空值校验，数据库操作使用参数化查询。

## 四、任务状态与持久化

- 状态限定为：等待中、运行中、已完成、失败、已取消、已中断。
- 每次状态变更立即写入 SQLite。
- 保存创建时间、开始时间、结束时间、当前阶段、模型、文件关联、报告路径和安全错误摘要。
- 不保存 API 密钥、Cookie、授权头、完整异常堆栈或网页原始内容。
- 进度使用固定阶段和说明文字，不生成没有依据的百分比。
- SQLite 只恢复可见状态与报告，不负责恢复中断任务的继续执行。

## 五、前端需求

- 使用 React + TypeScript + Vite，保持一个主要页面。
- 使用 Ant Design 实现表单、文件上传、状态提示、按钮和响应式布局。
- 使用浏览器 `fetch` 访问 API，首版不引入 Redux 或复杂查询框架。
- 主题输入必须有长度限制、必填校验和首尾空白清理。
- 任务提交后禁用重复提交；任务结束、失败或取消后恢复操作。
- 轮询必须在任务结束、组件卸载或服务异常达到上限时停止。
- 支持取消请求，并区分“正在取消”和“已取消”。
- 报告使用 `react-markdown` 展示，不启用原始 HTML，也不执行报告中的脚本。
- 页面刷新后通过最近任务接口恢复任务和报告。
- 密钥只由后端从 `.env` 读取，前端代码、构建变量和浏览器存储均不得包含密钥。

## 六、模型配置

- 首版只提供 Qwen 和 DeepSeek 两种聊天模型选择。
- Qwen 使用 `DASHSCOPE_API_KEY` 和 `QWEN_BASE_URL`。
- DeepSeek 使用 `DEEPSEEK_API_KEY` 和 `DEEPSEEK_API_BASE`。
- 聊天模型和 Embedding 模型保持独立配置。
- 选择 DeepSeek 聊天模型时，FAISS 仍可使用 Qwen `text-embedding-v4`。
- 现有备用模型降级逻辑继续保留，但前端不暴露密钥和任意 Base URL。
- 模型标识由后端白名单提供，不能由前端提交任意字符串。

## 七、文件与 RAG

- 允许的扩展名必须根据 `mdify` 实际支持情况建立白名单。
- 文件名由服务端清理并重命名，保存位置必须位于 `workdir` 的任务目录内。
- 必须限制单文件大小、文件数量和单任务总大小；具体数值在 W5 根据解析性能测试确定并写入配置。
- 不接受客户端提供的本地绝对路径，也不能信任 MIME 类型或原始文件名。
- 文档转换为 Markdown 后，继续按 1000 字、150 字重叠切分。
- 片段继续使用内容哈希去重，metadata 保存来源、片段编号和文档哈希。
- 使用独立 Embedding 路由生成向量，并按任务目录保存 FAISS 索引和文档映射。
- 默认使用研究主题检索 Top-K 4 个片段，再注入现有 Agent。
- 网页和文档内容一律视为不可信证据；标签必须转义，内容中的指令不得执行。
- 不增加 ChromaDB、LangChain Retriever、pgvector 或第二套 RAG 实现。

## 八、安全与质量

- `.env`、密钥、Cookie、授权头、数据库文件和运行产物不得进入 Git。
- 上传接口必须防止路径穿越、同名覆盖、超限上传和不支持格式。
- 报告下载只能通过任务编号定位服务器已登记的报告，不能接收任意路径。
- 前后端日志都要隐藏密钥、授权头、上传绝对路径和模型原始错误详情。
- 后端新增功能必须通过 pytest、Ruff、相关 mypy 和编译检查。
- 前端新增功能必须通过 TypeScript 类型检查、核心组件测试和生产构建。
- 核心离线测试不得调用真实模型 API；真实 API 只用于用户明确发起的验收。
- 每完成一个开发阶段，必须同步开发计划并提交推送。

## 九、非功能边界

- 目标环境是个人电脑或个人演示服务器，不承诺公网多用户并发。
- 不承诺进程退出后继续执行研究任务。
- 不实现账号、权限、租户、计费、配额和审计平台。
- 不引入 Redis、Celery、消息队列、SSE、WebSocket、微服务或多 worker。
- 如未来需求突破这些边界，必须先单独修改项目范围和开发计划，再开始编码。
