# Agent 与 RAG 离线评测

## 一、目标与边界

A3 提供一套轻量、可复现的开发者评测基线，用于在修改文档切分、FAISS 检索、Agent 活动、证据或引用逻辑后发现回归。它由命令行脚本、固定 JSON 输入、确定性指标和离线测试组成，不增加前端页面、API、数据库表或评测历史系统。

评测只回答以下问题：

- 人工标注的相关片段是否进入 Top-K。
- Agent 任务是否到达预期终态，活动是否全部收敛。
- 预期的活动、成功工具和证据类型是否出现。
- 报告引用是否可以追溯到 A2 收集的证据。

评测不判断隐藏推理质量、工具选择是否最优、正文事实是否正确，也不判断某句话是否被证据在语义上充分支持。

## 二、RAG 离线回归评测

运行：

```powershell
python scripts/evaluate_rag.py
```

默认读取 `evals/rag_cases.json`，输出：

- `workdir/evaluations/rag_report.json`：机器可读结果。
- `workdir/evaluations/rag_report.md`：人工审阅摘要与失败用例。

评测集包含 5 份内嵌中文资料和 50 条人工标注问题，按生产参数切分为 7 个片段，并覆盖解析校验、缓存、切分、索引、模型路由、Agent 执行、任务稳定性、证据引用、安全边界、同一文档后续片段及跨文档多证据查询。相关证据使用“来源文件名 + 必须包含的证据锚点”标注，避免只命中文件但取错片段也被算作成功。

指标定义：

```text
Recall@K = Top-K 中命中的不同标注证据数 / 标注证据总数
HitRate@K = 至少命中一条标注证据的用例数 / 全部用例数
RR@K = 第一个相关片段排名的倒数；Top-K 未命中时为 0
MRR@K = 全部用例 RR@K 的宏平均
```

当前固定基准：

| K | Recall@K | HitRate@K | MRR@K |
| ---: | ---: | ---: | ---: |
| 1 | 69.00% | 70.00% | 70.00% |
| 3 | 96.00% | 96.00% | 81.67% |
| 4 | 100.00% | 100.00% | 82.67% |

门禁要求为 Recall@4 不低于 90%、MRR@4 不低于 80%。通过返回退出码 `0`，低于门禁返回 `1`，输入无效返回 `2`。

评测复用生产代码中的文档切分、metadata、内容去重、真实 FAISS 建库、搜索和 `RetrievedChunk` 映射。唯一替换的是 Embedding：使用基于 BLAKE2b 的固定中文字符 N-gram 与英文词元哈希向量，因此完全不访问模型 API，跨进程结果也保持稳定。

这套分数用于检索回归，不代表 Qwen Embedding 的线上语义能力。同义改写、跨语言和语义泛化应另行使用真实 Embedding 做人工验收，不能与此基准混写。

## 三、Agent 执行结果评测

运行格式示例：

```powershell
python scripts/evaluate_agent_results.py `
  --input evals/agent_results.example.json `
  --output workdir/evaluations/agent_report.json
```

输入由 `expected` 和 `snapshot` 两部分组成：

- `expected` 声明预期终态、是否需要报告、必需活动、必需工具、最低证据数量、证据类型和引用门槛。
- `snapshot` 只保存现有任务接口已经公开的安全字段：终态、报告是否可用、活动、证据和引用核验结果。

真实用例可以从 `GET /api/tasks/{task_id}` 的响应中复制 `status`、`report_available`、`activities`、`evidence` 和 `citation_validation`，再补充人工预期条件。输入模型只接受文档定义的安全字段，额外的隐藏推理、工具参数或原始输出会被直接拒绝；命令行校验错误不会回显输入值。不要把模型隐藏推理、工具参数、网页原文、密钥或请求头写入评测文件。

评测前还会确定性校验活动编号和证据编号唯一性，以及引用总数、有效引用数、异常引用数、证据标签、覆盖率和通过状态之间的一致性。结构不一致的快照属于无效输入，不会被聚合为看似正常的比例。

聚合报告保留每项指标的分子、分母和比例。零分母显示 `N/A`，不会伪装成 100%。当前指标包括：

- 预期终态匹配率和成功任务完成率。
- 活动终态率、必需活动覆盖率和必需工具覆盖率。
- 工具成功率。
- 引用可追溯率和证据引用覆盖率。
- 用例通过率与逐条失败原因。

`evals/agent_results.example.json` 只说明格式并验证评测程序，不是实际模型成绩。真实基准必须由固定问题、固定人工预期和真实运行快照构成，并注明所用模型与日期。

## 四、维护规则

1. 修改检索逻辑后必须运行 RAG 离线评测和相关 pytest。
2. 新增评测用例时保证编号唯一，证据锚点确实存在且不会跨越切分边界。
3. 不得为了提高分数删除失败用例；应先记录失败原因，再决定修改检索或修正错误标注。
4. 离线哈希基准和真实 Embedding 结果必须分开命名、分开报告。
5. Agent 结构指标不得命名为“事实准确率”“幻觉率”或“推理正确率”。
6. 生成报告保存在 `workdir/evaluations/`，不提交运行产物。
