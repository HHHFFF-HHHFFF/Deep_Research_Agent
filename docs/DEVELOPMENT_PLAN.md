# 稳定 Web 前端开发计划

## 一、当前指针

- 最后更新：2026 年 8 月 20 日
- 最终定位：本地单用户的个人深度研究助手
- 当前可用能力：React 完整研究界面、受限文件上传、真实格式解析与缓存、RAG 状态和文件详情、任务创建与轮询、任务取消、最近任务恢复、安全报告查看下载、统一研究运行入口、FastAPI、SQLite、命令行研究、Qwen／DeepSeek 路由、网页研究和 FAISS 本地 RAG
- 已完成阶段：W0 研究核心与本地 RAG、W1 稳定研究运行入口、W2 后端接口与任务管理、W3 React 单页输入界面、W4 任务闭环与历史恢复、W5 上传与真实格式 RAG 验收
- 当前阶段：W6 质量、打包与简历材料
- 下一步工作：统一启动方式、生产静态托管、演示说明和面试材料
- 当前阻塞：无

## 二、本次路线决定

项目保留现有 Agent、研究工具、模型路由和本地 RAG，在其外部增加一套稳定但克制的 Web 界面：

```text
React + TypeScript + Vite + Ant Design
                  ↓ HTTP／轮询
             FastAPI API
                  ↓
     研究运行入口 + AsyncIO 任务管理
        ↓                    ↓
现有工具型 Agent      SQLite 任务元数据
        ↓
网页研究 + 本地文档 RAG（FAISS）
        ↓
Markdown 报告文件
```

选择前后端分离，是为了获得清晰的接口边界、稳定的错误处理、刷新后恢复任务状态以及可测试的用户交互。SQLite 只保存任务、文件和报告元数据；FAISS 继续负责文档向量检索，两者职责不重叠。

首版采用普通 HTTP 接口和 1 至 2 秒轮询，不使用 SSE 或 WebSocket。研究任务在 FastAPI 单进程内通过 AsyncIO 管理，同一时间只运行一个任务，不引入 Redis、Celery 或独立工作进程。

## 三、产品完成标准

用户能够在浏览器中完成以下闭环：

1. 输入研究主题并选择 Qwen 或 DeepSeek。
2. 可选上传本地资料，资料进入已经完成的 FAISS RAG 流程。
3. 创建研究任务后看到真实阶段状态，不能重复提交。
4. 可以取消正在运行的任务，并看到清晰的失败原因。
5. 页面刷新后可以恢复最近任务和已完成报告。
6. 在线查看并下载 Markdown 报告。

这里的“稳定”特指输入校验、任务互斥、状态恢复、取消、超时与错误反馈可靠，不代表多用户、高并发或分布式部署。

- 保留网页搜索、抓取、分析和报告工具

- 完成会话级 FAISS 索引、Top-K 4 检索和不可信证据注入
- 命令行支持重复传入 `--file`
- 完成 P1-M1 代码规范基线和 P1-M2a 至 P1-M2d 高价值类型修复

验收结果：本地 RAG 的 7 个离线测试通过，其中包含真实 FAISS 与虚拟 Embedding 集成测试；当前全套 31 个测试通过。

### W1：提取稳定的研究运行入口

状态：已完成

目标：不重写 Agent，只把命令行中的初始化、配置覆盖、RAG 准备和报告返回整理成可复用异步函数。

完成内容：

- 新增轻量 `research_runner` 模块
- 定义研究输入和研究输出数据模型
- 输入包含研究主题、模型选择和文件列表
- 支持同步或异步阶段回调，阶段限定为初始化、研究中、完成、失败和取消
- 在组件初始化和 Agent 调用期间监听协作式取消信号
- 命令行改用同一运行入口，原有参数保持兼容
- 优先读取 Reporter 实际生成的 Markdown 文件，缺失时回退到 Agent 结果
- 使用替身完成离线测试，全程不调用真实模型 API

明确不做：应用容器、事件总线、插件系统、通用工作流引擎和多 Agent 编排。

验收结果：命令行参数保持兼容；研究入口可独立测试；模型覆盖、阶段回调、取消、失败、敏感错误隐藏和报告文件读取均有离线测试；全套测试由 31 项增加到 37 项并全部通过，Ruff、格式检查、W1 局部 mypy 和编译检查通过。

### W2：实现 FastAPI、SQLite 与单进程任务管理

状态：已完成

目标：提供前端所需的最小 API，并让任务状态可在页面刷新后恢复。

完成内容：

- 增加 FastAPI 应用和统一错误响应
- 使用 Pydantic 校验请求与响应
- 使用 SQLAlchemy 2 和 SQLite 保存任务、上传文件和报告路径
- 使用进程内 AsyncIO 任务管理器，同一时间只允许运行一个研究任务
- 使用协作式取消，不强制终止线程或进程
- 应用启动时把遗留的“运行中”任务标记为“已中断”
- 应用关闭时等待任务收敛，超时后取消并标记为“已中断”
- 上传文件使用服务器生成名称，并限制路径、扩展名、空文件和大小
- 未知异常只保存安全摘要，不向接口暴露令牌、堆栈或绝对路径
- 提供以下接口：
  - `GET /api/health`
  - `POST /api/files`
  - `POST /api/tasks`
  - `GET /api/tasks`
  - `GET /api/tasks/{task_id}`
  - `POST /api/tasks/{task_id}/cancel`
  - `GET /api/tasks/{task_id}/report`

任务状态限定为：等待中、运行中、已完成、失败、已取消、已中断。进度只展示真实研究阶段和文字说明，不伪造百分比。

验收结果：13 项 W2 异步接口测试覆盖健康检查、OpenAPI 文档、成功报告、最近任务、上传安全、文件关联、重复提交、取消、稳定失败、未知异常脱敏、启动恢复和关闭中断；全套 50 项测试通过，测试不连接真实模型。

### W3：搭建 React 单页前端并完成任务提交

状态：已完成

目标：完成稳定、清晰的研究输入界面。

完成内容：

- 使用 React、TypeScript 和 Vite 建立 `frontend/`
- 使用 Ant Design 提供表单、上传、提示、状态和布局组件
- 保持单页布局，不引入前端路由
- 提供研究主题、模型选择、可选文件上传和开始按钮
- 使用浏览器 `fetch` 调用 API，不额外引入复杂状态框架
- 处理空值、加载、重复点击、网络错误和服务不可用状态
- API 地址通过环境变量配置，密钥永远不进入前端
- 限制资料为 `.md`、`.txt`、`.pdf` 和 `.docx`，最多 5 个且单个不超过 10 MB
- 使用中文错误反馈处理后端拒绝、网络中断和服务未启动
- 提供桌面、平板和手机宽度下可用的响应式布局
- 模型选项在桌面端左右并排，卡片说明从左到右自然换行且始终可见

验收结果：6 项前端离线测试覆盖空主题、模型切换、文件上传、任务创建、后端业务错误和服务不可用；TypeScript 类型检查与 Vite 生产构建通过，构建过程不读取后端密钥。

### W4：完成轮询、取消、报告与历史恢复

状态：已完成

目标：打通完整用户闭环，并实现本项目所需的前端稳定性。

完成内容：

- 每 1.5 秒轮询当前任务，任务结束或组件卸载后自动停止
- 显示当前阶段、运行时间和安全化错误信息
- 支持取消任务，取消过程中禁用重复操作
- 使用安全的 Markdown 渲染器展示报告，不启用原始 HTML
- 支持下载 Markdown 报告
- 展示最近 8 个任务，点击后可恢复任务状态和报告
- 刷新页面后优先恢复活动任务，再根据本地任务编号或最近列表恢复界面
- 连续 3 次连接失败后暂停轮询，并提供手动重新连接
- 使用 AbortController 清理报告请求和状态请求，避免卸载后继续更新界面

验收结果：完成、失败、取消、中断和后端离线状态均有明确中文界面；报告原始 HTML 不会执行，外部链接使用安全属性；12 项前端离线测试、TypeScript 类型检查和 Vite 生产构建全部通过，后端 50 项离线测试与 Ruff 检查继续通过。

### W5：强化上传文件与现有 RAG 验收

状态：已完成

目标：在 W2 已完成安全上传和路径传递的基础上，完成真实解析性能验证与带文件研究验收，不另建检索系统。

完成内容：

- 实测 mdify 底层 MarkItDown 对 Markdown、TXT、PDF、DOCX 均可生成非空内容，保留四种格式白名单
- 微型真实格式样本解析约 0.016 至 0.033 秒，约 10 MB 纯文本解析约 0.45 秒
- 使用不加载音频、远程模型和 PDF 表格增强的受限解析入口，设置 30 秒超时并缓存 Markdown 结果
- 最终限制为单文件 10 MB、最多 5 个、单次研究总量 25 MB、单文件解析后最多 20 万个字符
- 校验 PDF 文件头和 DOCX 压缩结构，拒绝空白、伪格式、解析失败、解析超时和文字过长的文件
- 复用现有文档切分、内容哈希、Embedding、FAISS 和 Top-K 逻辑
- 在任务详情中展示已使用的文件名和 RAG 是否启用
- 增加真实四种格式经过解析、去重、虚拟 Embedding 和真实 FAISS 检索的端到端离线测试
- 修复 React StrictMode 二次挂载导致最近任务持续加载的问题，并增加回归测试

验收结果：路径穿越、不支持格式、空文件、伪格式、单文件超限、任务总量超限和解析内容超限均被拒绝；四种真实格式可以进入既有 FAISS，重复文档第二次索引数量为 0。后端 58 项、前端 13 项测试全部通过，Ruff、TypeScript 类型检查和 Vite 生产构建通过。

## 五、明确排除项

首版不实现：

- 用户注册、登录、权限、多租户和多人协作
- PostgreSQL、Redis、Celery、RabbitMQ 和独立任务工作进程
- SSE、WebSocket 和复杂实时事件系统
- Next.js、服务端渲染、搜索引擎优化和多页面管理后台
- 微服务、Docker Compose、Kubernetes 和云原生编排
- 支付、配额、运营后台和公开 SaaS 部署
- 多套 RAG 框架或多个向量数据库
- Agent 持久化长期记忆、多 Agent 辩论和自动评测平台

如果未来确实出现多用户或多进程需求，再单独评估 PostgreSQL、Redis 和任务队列；它们不提前进入当前代码。

## 六、范围闸门

每个新需求开始前必须回答：

1. 是否直接服务于“输入主题、结合可选资料并生成研究报告”？
2. 是否改善输入、执行、恢复、错误反馈或报告查看中的稳定性？
3. 是否可以复用现有 Agent、研究工具或 FAISS RAG？
4. 是否引入了明确排除的多用户、分布式或平台化能力？
5. 是否能在一个开发阶段内完成并用离线测试验收？

第 4 项为“是”时默认不做；第 5 项为“否”时先拆分需求，不直接开发。

## 七、每步工作流程

每次开发前：

1. 阅读本文档的当前指针。
2. 检查 Git 工作区和上一步验收结果。
3. 向用户说明当前进度、本次唯一目标和明确不做的内容。

每次开发后：

1. 运行本阶段相关的离线测试和静态检查。
2. 更新当前指针、阶段状态、验收结果和变更记录。
3. 每完成一个阶段提交并推送一次；除非用户明确要求合并多个阶段。

## 八、面试解释口径

> 这是一个本地单用户的个人深度研究助手。React 前端负责主题输入、文件上传、任务状态和报告展示，FastAPI 提供清晰的 API 边界，SQLite 让刷新后仍可恢复任务和报告元数据。后端复用工具型 Agent 完成网页研究，并通过独立 Embedding 与 FAISS 把本地资料作为证据加入研究。为了控制个人项目边界，首版只使用单进程 AsyncIO 和 HTTP 轮询，没有引入 Redis、Celery、多租户或微服务。

面试中重点解释：

- 为什么使用 React 单页应用而不需要 Next.js 或服务端渲染
- FastAPI 如何把长耗时研究任务转换为创建、查询和取消接口
- 为什么状态元数据使用 SQLite，而向量检索继续使用 FAISS
- 页面刷新、任务互斥、取消和进程重启如何处理
- Qwen 与 DeepSeek 如何通过统一兼容接口切换和降级
- 本地文档如何切分、去重、Embedding、Top-K 检索并防止提示注入
- 为什么使用轮询而不是 SSE、WebSocket 或分布式任务队列
